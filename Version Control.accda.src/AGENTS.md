# AGENTS.md - Working With Exported Microsoft Access Source Files

This folder is a Microsoft Access database exported to text files by the MSAccess
VCS add-in. Editing these files is how you change the database, but edits only
take effect when the add-in imports them back in Access. You cannot run or test
this code directly, and the add-in is required to build a working database from it.

This file and everything under `vcs-agent-docs/` are generated by the add-in and
**rewritten on every export**. Keep your own project notes elsewhere.

## Non-negotiable rules

1. **Do not change file encoding.** Source files are UTF-8, and most are UTF-8
   *with BOM* (bytes `EF BB BF`). Re-saving without the BOM makes import fail or
   silently corrupt the object.
2. **Do not change line endings.** Access `LoadFromText` requires CRLF (`\r\n`).
3. **Do not edit** `vcs-index.idx` (binary change index), `.frx` files (binary OLE
   data), or `.thmx` files (ZIP archives — edit the extracted contents instead).
4. **Do not rename a file** without changing the object name stored inside it.
   File names must match object names exactly.
5. **Do not alter VBA scaffolding:** `Attribute VB_Name` lines, the
   `VERSION`/`BEGIN`/`END` block at the top of a `.cls`, or module-level
   `Attribute VB_*` lines. The code below them is yours to edit.

## Which file do I edit?

| To change | Edit | Read first |
|---|---|---|
| VBA in a standard module | `modules/<name>.bas` | `vcs-agent-docs/vba-modules.md` |
| VBA in a class module | `modules/<name>.cls` | `vcs-agent-docs/vba-modules.md` |
| Form or report code-behind | `forms/<name>.cls`, `reports/<name>.cls` | `vcs-agent-docs/vba-modules.md` |
| Form or report layout | `forms/<name>.form`, `reports/<name>.report` | `vcs-agent-docs/forms-reports.md` |
| Conditional formatting rules | the form's or report's companion `.json` | `vcs-agent-docs/forms-reports.md` |
| Query logic | `queries/<name>.sql` — the sole source of truth for SQL | `vcs-agent-docs/queries.md` |
| Query properties or design layout | `queries/<name>.json` | `vcs-agent-docs/queries.md` |
| A macro | `macros/<name>.macro` | — |
| A table definition | `tbldefs/<name>.xml` and `.json` | — |
| A connection string | `.env` at this folder's root (gitignored) | `vcs-agent-docs/troubleshooting.md` |
| Tests | a test module under `modules/` | `vcs-agent-docs/testing.md` |

Export format 5.0.0 renamed several object types from the overloaded `.bas`
extension: forms to `.form`, reports to `.report`, macros to `.macro`, and queries
to `.sql` plus `.json`. Older projects still use `.bas` for these, so check which
extensions are actually present. Import accepts both.

## File placement follows the `@Folder` annotation

The add-in reads Rubberduck-style `'@Folder("Category")` annotations and exports
components into matching subdirectories, with dots as path separators:
`'@Folder("Components.ADP")` lands in `modules/Components/ADP/`. Components with no
annotation stay at the root of `modules/`, `forms/`, or `reports/`. Import scans
subdirectories recursively.

**The annotation decides where the file belongs on disk, not the folder you happen
to be editing in.** This is the most common way agents corrupt a project:

- For modules, the annotation is in the `.bas` or `.cls` itself. For forms and
  reports it lives in the `.cls` code-behind only — not in `.form`/`.report`,
  `.json`, or `.svg`.
- Before creating or moving a component, search the **entire** `modules/`, `forms/`,
  or `reports/` tree for an existing file with the same base name (for modules,
  match on `Attribute VB_Name`). Edit that file in place rather than creating a
  second copy elsewhere.
- If two copies exist, such as `modules/modFoo.bas` and `modules/Tests/modFoo.bas`,
  build imports **both** and the last one silently wins. No error is shown.
- Build removes a misplaced duplicate automatically when exactly one copy sits in
  its annotation-derived folder. Ambiguous cases are left alone with a warning.
  Removing a duplicate form or report deletes its whole source group together
  (`.form`/`.report` plus `.cls`, `.json`, and `.svg`).

To relocate a component, change its `'@Folder` annotation and let the next export
move the file.

## How changes get back into Access

Ask the user to run a **merge build** from the add-in ribbon, which imports changed
source files into the existing database. A **full build** creates a new database
from source instead, and **export** goes the other way, writing database objects
out to these files. When a source file and its database object have both changed,
the add-in detects the conflict and prompts the user to choose which version wins.
